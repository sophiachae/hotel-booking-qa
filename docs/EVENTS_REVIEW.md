# 이벤트 명세 리뷰 (release/1.2)

> 근거: [EVENTS.md](EVENTS.md), [SPEC.md](SPEC.md)만 사용 (코드 미확인) · 매트릭스: [EVENTS_MATRIX.md](EVENTS_MATRIX.md)

명세가 모호하거나 빠진 부분 목록입니다. 명세에 없는 내용은 "명세 없음"으로 표시했습니다.

## A. 전체 이벤트 공통

| # | 항목 | 문제 |
|---|---|---|
| A1 | 속성 필수 여부 | 모든 속성 표에 "필수" 칸이 없습니다. 속성이 빠져도 되는지, `null`이 들어가도 되는지 **명세 없음**. `null`이 허용된다고 적힌 건 `hotel_viewed`의 `nights`, `guests` 두 개뿐입니다. |
| A2 | 새로고침·뒤로가기 | 새로고침하거나 뒤로가기로 돌아왔을 때 이벤트를 다시 보내는지 **명세 없음**. 해당 이벤트는 `hotel_viewed`, `booking_started`, `$pageview`이고, 다음 화면에서 보내는 이벤트도 다음 화면을 새로고침하면 같은 문제가 있습니다. |
| A3 | 중복 클릭 | 버튼을 빠르게 두 번 눌렀을 때 한 번만 보내는지 **명세 없음** (검색 버튼, "이 객실 예약" 버튼). |
| A4 | "다음 화면"의 범위 | 다음 화면이 정확히 어느 화면인지 **명세 없음**. 다음 화면이 안 열리는 경우(탭 닫기, 다른 사이트로 이동, 새 탭에서 열기)도 **명세 없음**. 참고로 `sessionStorage`는 탭마다 따로 저장됩니다. |
| A5 | 저장값 처리 | 다음 화면에서 보낸 뒤 저장값을 지우는지, 얼마나 보관하는지, 여러 개가 쌓이면 모두 보내는지 아니면 덮어쓰는지 **명세 없음**. |
| A6 | `timestamp` 형식 | 형식(ISO 문자열인지, 숫자인지)과 기준 시간대 **명세 없음**. |
| A7 | 트래킹 꺼짐 | 키가 없을 때 `sessionStorage` 저장과 `X-Analytics-Distinct-Id` 헤더 전송까지 하지 않는지 **명세 없음**. 명세에는 "PostHog로 요청을 보내지 않는다"만 있습니다. |
| A8 | 로딩 전 동작 | 스니펫이 다 불러와지기 전에 생긴 이벤트를 큐에 담는지 아니면 버리는지 **명세 없음**. |
| A9 | `$pageview` 대상 | 모든 화면이 대상인지 **명세 없음**. Mock OAuth 화면이 포함되는지도 **명세 없음**. |

## B. 사용자 식별

| # | 항목 | 문제 |
|---|---|---|
| B1 | 순서 | `identify`를 `login_completed`·`signup_completed`보다 먼저 하는지 나중에 하는지 **명세 없음**. 순서에 따라 이벤트의 `distinct_id`가 익명 ID일지 회원 id일지 달라집니다. |
| B2 | 세션 만료 감지 | 언제 감지하는지(화면에 들어갈 때마다 `/api/auth/me`를 부르는지) **명세 없음**. |
| B3 | `login_provider` 설정 시점 | 로그인할 때 정하는지, 가입할 때 정하는지, 값을 소문자로 바꾸는지(DB에는 `EMAIL`, 속성 값은 `email`) **명세 없음**. |
| B4 | 탭 여러 개 | 다른 탭에서 로그인하거나 로그아웃했을 때의 동작 **명세 없음**. |

## C. 개인정보

| # | 항목 | 문제 |
|---|---|---|
| C1 | 지우는 대상 | 어떤 속성에서 쿼리를 지우는지 **명세 없음** (`$current_url`만인지, `$referrer`, `$pageleave`도 포함인지). |
| C2 | `returnTo` 처리 | "`returnTo` 안쪽 주소 포함"이 `returnTo` 전체를 지운다는 뜻인지, 안쪽 주소의 `email` 같은 값만 지운다는 뜻인지 모호합니다. |
| C3 | 대상 키 목록 | 지우는 키가 `email`, `phone`, `name` 세 개뿐인지 **명세 없음**. 대소문자 변형(`Email`)도 지우는지 **명세 없음**. |

## D. 이벤트별

| # | 이벤트 | 문제 |
|---|---|---|
| D1 | `search_submitted` | 검색 결과 화면에서 "검색 조건 변경"(`results-modify-search`)을 거쳐 다시 검색할 때도 보내는지 **명세 없음**. |
| D2 | `search_submitted` | `nights` 계산 방법 **명세 없음** (체크인·체크아웃 차이로 추정). |
| D3 | `hotel_viewed` | 주소에 일정이 있는데 값이 틀린 경우(예: 날짜 형식 오류로 API 400): "조회 실패"로 보고 안 보내는지, `has_stay=false`로 보내는지 모호. |
| D4 | `hotel_viewed` | 일정이 일부만 있을 때 `has_stay=false`로 읽히지만 확실하지 않음. |
| D5 | `hotel_viewed` | `has_stay=false`일 때 `available_room_count` 값 **명세 없음** ("예약 가능" 기준이 없음). |
| D6 | `hotel_viewed` | `city`가 호텔 정보의 도시인지, 검색 주소의 도시인지 모호 (표에는 "호텔 도시"). |
| D7 | `room_selected` | 일정 없이 들어온 경우 버튼이 눌리는지 **명세 없음**. 눌린다면 `nights`·`guests` 값도 **명세 없음** (타입이 `integer`라 `null` 불가). |
| D8 | `booking_started` | 예약 화면에서 로그인 후 같은 화면으로 돌아오면 또 보내는지, 회원 전용 모드에서 로그인 후 폼이 처음 보일 때 보내는지 **명세 없음**. |
| D9 | `booking_started` | 예약 화면 자체가 실패한 경우(`booking-error`, 예: 없는 객실) 보내지 않는지 **명세 없음**. |
| D10 | `booking_started` | `total_price`가 "화면에 표시한 값"과 "1박 요금 × 숙박 일수" 중 무엇인지 모호 (두 값이 다를 때). |
| D11 | `reservation_completed` | 화면 이벤트가 완료 화면에서 전송된다고 추정되지만 명시 안 됨. 완료 화면 새로고침 시 재전송 여부 **명세 없음**. |
| D12 | `reservation_completed` | 서버 큐 전송 실패 시 재시도, 서버 종료 시 flush 여부 **명세 없음**. |
| D13 | `reservation_completed` | 회원 예약의 화면·서버 이벤트가 같은 `distinct_id`로 묶이는지, 헤더가 비었거나 잘못됐을 때 처리 **명세 없음**. |
| D14 | `reservation_completed` | 화면·서버 이벤트 값(`total_price` 등)이 달라도 정상인지 **명세 없음**. |
| D15 | `reservation_cancelled` | `days_before_check_in` 계산 기준 **명세 없음** (한국 시간/UTC, 체크인이 내일이면 1인지). |
| D16 | `reservation_cancelled` | 다른 이벤트와 달리 `guests`가 없음. 의도인지 **명세 없음**. |
| D17 | `reservation_cancelled` | 서버 이벤트가 없음. 의도인지, 집계 기준이 무엇인지 **명세 없음**. |
| D18 | `signup_completed` | 이메일 가입은 즉시 로그인되는데 `login_completed`도 함께 보내는지 **명세 없음**. 다음 화면이 `returnTo` 화면인지도 명시 안 됨. |
| D19 | `login_completed` | 카카오 버튼을 누르고 떠났다가 나중에 이메일로 로그인하면 남은 저장값이 `method`로 잘못 쓰일 수 있음. 저장값 유효 시간 **명세 없음**. |
| D20 | `login_completed` | 실패 코드 목록이 "등"으로 끝나서 모든 실패 코드에서 저장값을 지우는지 불명확. |
| D21 | `login_completed` | 소셜 첫 로그인(자동 가입)인지 구분하는 속성이 없음. 의도인지 **명세 없음**. |
| D22 | `login_completed` | 이미 로그인한 상태에서 다시 로그인했을 때의 동작 **명세 없음**. |
| D23 | `logout` | "API가 끝났을 때"가 성공 시만인지, 실패해도 보내는지 모호. |
| D24 | `logout` | 세션이 이미 만료된 상태에서 로그아웃하면(API는 200) `logout`을 보내는지 **명세 없음**. |
